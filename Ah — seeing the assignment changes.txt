The queries I'd make sure you have

The assignment explicitly requires a multi-hop traversal and at least one query that would be awkward in a relational database.

1. Find accounts sharing a device
MATCH (c:Customer)-[:USES]->(d:Device)<-[:USES]-(other:Customer)
WHERE c.id = $customerId
  AND c <> other
RETURN other

Simple, but useful.

2. Find suspicious multi-hop connections

This is much more interesting:

MATCH path =
  (c:Customer)-[:USES]->(d:Device)
  <-[:USES]-(other:Customer)
  -[:OWNS]->(a:Account)
  -[:MADE]->(t:Transaction)
WHERE c.id = $customerId
  AND t.isFraud = true
RETURN path
LIMIT 20

Now you're finding:

Customer → Device → Another Customer → Account → Fraudulent Transaction

That's exactly the kind of relationship traversal the assignment is looking for.

3. Find a fraud ring

For example:

MATCH (c1:Customer)-[:USES]->(d:Device)<-[:USES]-(c2:Customer)
MATCH (c2)-[:USES]->(d2:Device)<-[:USES]-(c3:Customer)
WHERE c1 <> c2
  AND c2 <> c3
RETURN c1, c2, c3, d, d2

You can describe this as:

"Detect clusters of customers connected through shared devices."

Why this is a particularly good assignment choice

The assignment says they're evaluating data modeling, engineering architecture, and your judgment in choosing a problem where graph genuinely earns its place.

Fraud detection lets you demonstrate all three:

Data modeling

Customer → Device → Customer → Account → Transaction

Graph queries

Multi-hop traversal and relationship discovery.

Product thinking

An investigator actually has a reason to explore those relationships.

UI

Risk dashboard + investigation workflow + graph visualization.

Engineering

Backend → Neo4j driver → CognoDB → parameterized Cypher.

Architecture discussion

You can explicitly explain that this is a graph-centric investigation/risk layer, rather than claiming a graph database should replace a financial ledger.

One thing I'd change from my previous answer

For this assignment, don't spend time debating whether CognoDB is the right graph database. The assignment explicitly defines CognoDB as the managed graph database and tells you to connect through the official Neo4j driver.

Your job is instead to make the best possible application demonstrating why a graph database is useful.

If this were my take-home, FraudLens would be one of my top choices. It gives you a very natural answer to the interview question:

"Why did you need a graph database here?"

And the answer is not theoretical — you can literally show the interviewer a fraud network that requires multiple hops to discover.
